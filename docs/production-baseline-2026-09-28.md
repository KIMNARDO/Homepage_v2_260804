## 운영 버전 대조

- 원격 `origin/main`이 위 커밋을 가리키는 것을 확인했다.
- 운영 서버의 공개 HTML 11개와 해당 커밋의 빌드 결과를 비교했다. Windows checkout에서 발생한 CR 문자를 제외하면 11개 모두 일치한다.
- 각 페이지가 사용하는 JavaScript와 CSS 15개를 내려받아 비교했다. 15개 모두 파일명과 바이트 내용이 일치한다.
- AutoCAD와 SOLIDWORKS SVG 두 파일은 Windows checkout의 CRLF 때문에 빌드 파일명이 달라졌다. Git에 저장된 원본 바이트(LF)로 체크아웃하고 `.gitattributes`에 두 파일의 LF 규칙을 추가해 운영 사이트와 같은 이름을 재현했다. 이미지 내용은 변경하지 않았다.
- 검사 결과와 운영 HTML 사본은 `output/production-baseline/`에 있다. 이 폴더는 버전 관리와 배포 대상에서 제외된다.

이는 공개 프런트엔드 빌드의 일치 확인이다. 운영 환경 변수나 비공개 서버 데이터를 복사하지 않았으며 실제 문의 전송은 실행하지 않았다.

## 화면 확인

- 로컬 홈페이지가 운영 버전의 제목, AI 질문창 및 히어로로 표시되는 것을 확인했다.
- 데스크톱 화면에서 자동차 → 항공 → 건축 → 자동차 탭 전환과 선택 상태를 확인했다.
- 좁은 화면에서는 운영 사이트와 같은 모바일 제목과 메뉴 구성이 표시된다.
- 검증 중 브라우저의 오류·경고 로그는 없었다.
- 데스크톱 검증 화면은 `output/production-baseline/local-desktop.png`에 저장했다. 검증용 화면 크기 설정은 해제했다.

개발 의존성은 이 폴더에 별도로 설치했다. 기존 수정본의 `node_modules`를 가리키던 임시 연결은 제거했다. 이 환경에는 npm 실행 파일이 없어 `package-lock.json`을 pnpm으로 가져와 설치했으며, 가져온 설치 기록은 `output/production-baseline/`에 보관했다. 기준 잠금 파일은 기존 `package-lock.json`을 유지한다. 설치 후 다시 빌드해 11개 HTML과 15개 JS/CSS가 운영 버전과 일치함을 재확인했다.

## 개발 시작점

운영 사이트의 현재 구성을 유지한 상태에서 필요한 부분을 순서대로 개선한다.

- 검정 배경과 연두색 포인트, 기존 로고 및 제목.
- 자동차 BOM, 항공 구성·리비전, 건축 디지털 트윈의 산업별 히어로 장면.
- AI 질문창과 추천 업무 버튼.
- 제품 페이지, 도입 상담, 브로슈어, 기존 URL과 섹션 ID.
- 기존 분석 이벤트 및 문의 처리 코드.

컴포넌트 디자인 요청은 카드·버튼·아이콘·탭의 스타일에 적용한다. 히어로 전체를 다른 구조로 교체하는 요청으로 확대 해석하지 않는다. 여러 부품을 보여주는 후속 개선도 이 운영 버전의 장면과 동작을 기준으로 검토한다.

## 실행 및 비교

아래 명령은 현재 개발 폴더에서 실행한다.

```powershell
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5174 --strictPort
```

운영 기준과 다시 대조할 때는 먼저 빌드한 뒤 검사한다.

```powershell
node node_modules/vite/bin/vite.js build
node scripts/verify-production-baseline.mjs
```

검사 도구는 공개 페이지와 JS/CSS만 읽고 비교 결과를 로컬에 저장한다. 개선 후에는 운영 사이트와 차이가 나는 것이 정상이며, 이 도구의 실패를 이유로 개선 내용을 자동으로 되돌리지 않는다.

이번 작업은 개발 기준을 운영 버전에 맞추는 작업이다. 새로운 디자인이나 기능 변경, 운영 배포는 포함하지 않았다.
