# 모바일 레이아웃·다크 모드 검토

검토용 로컬 주소: http://127.0.0.1:5174/

사용자가 표시한 15곳과 휠 스크롤 문제를 수정한 로컬 작업이다. 운영 게시, Git 커밋 및 푸시는 승인 대상이며 수행하지 않았다.

## 원인과 변경

- 히어로 마지막 장면의 이동 대상이 `#platform`으로 남아 있어 앞에 추가된 `#news`를 건너뛰었다. 다음 위치와 하단 이동 링크를 소식으로 수정했다.
- 휠 입력 기준 18px는 너무 작았다. 80px 기준, 픽셀·줄·페이지 단위 정규화, 200ms 정지로 구분하는 제스처당 한 장면 처리로 바꿨다. 전환 중 남은 휠 입력이 소식을 넘기지 않도록 처리했다. 모바일 760px 이하와 터치는 브라우저 기본 스크롤을 사용한다. 입력창, 확대 제스처 및 열린 메뉴·대화상자에서는 히어로가 휠을 가로채지 않는다.
- 짝수 번째 섹션 배경을 밝은 고정색으로 지정한 CSS가 다크 모드보다 우선 적용됐다. 위치에 따른 규칙을 테마 변수로 수정하고 홈페이지용 보완 스타일에 다크 배경을 통일했다.
- 다크 본문 배경 `#101719`, 카드 `#192329`, 제목 `#f2f6f7`, 본문 `#a9b7bf`를 사용한다. 기존 히어로의 구조·산업 장면·AI 질문창은 유지한다.
- 제품 탭 자동 순환을 없애고 이전/다음 버튼, 현재 순서, 탭과 패널의 접근성 연결을 추가했다. 모바일은 하나의 탭이 화면 폭 안에 온전히 보이며 가로 스크롤로도 선택할 수 있다. 선택된 화면의 영상은 해당 화면이 보일 때만 재생한다.

AI·뷰어 내부 패널, 상단 내비게이션, 플랫폼·제품의 작은 라벨, 라이트 모드의 낮은 대비 라벨도 점검·보완했다.

모바일에서 본문을 덮던 우측 하단 상담·맨 위 고정 버튼을 숨기고, 상담 링크를 상단 메뉴 옆으로 이동했다. 상담은 한 번의 클릭으로 열리며 도입 흐름의 마지막 설명도 가려지지 않는다.

## 확인 결과

- 단위 테스트: 소식 8개와 휠 제스처 6개, 총 14개 통과.
- `node --check app.js`, `git diff --check` 통과. 기존 줄바꿈 경고만 존재.
- 최종 빌드 성공(2.58초): 실행 프로세스에만 `GOMAXPROCS=2`, `GOMEMLIMIT=64MiB`를 설정한 뒤 `node --max-old-space-size=256 --max-semi-space-size=2 node_modules/vite/bin/vite.js build` 실행. 운영·프로젝트 설정은 변경하지 않았다.
- 검토 중 시스템 메모리 압박으로 첫 빌드와 미리보기 탭이 종료됐으나, 미리보기를 복구하고 메모리 사용량을 제한한 빌드로 검증을 완료했다.
- 실제 데스크톱 휠 입력: 18px에서는 장면 유지, 120px 입력에서 한 장면 이동, 600px 입력에서도 한 장면만 이동. 마지막 장면 다음에는 소식이 상단 내비게이션 아래 132px 위치에 표시됐다.
- 실제 모바일 휠 입력: 페이지 맨 위에서 600px 이동 시 소식 섹션 상단이 244px 위치에 노출됐다. 히어로가 기본 스크롤을 막거나 플랫폼으로 이동시키지 않았다.
- 제품 화면 버튼: 01 → 02 → 03 → 04 → 05 → 01 순서와 선택된 패널 일치. 이전 버튼, Home/End 키, 가로 휠 스와이프도 확인.
- 320 / 390 / 496 / 1016 / 1263px에서 가로 넘침 없음. 320px 제목 잘림 없음. 320px 탭·레일 폭 262px, 390px 332px, 496px 438px로 일치.
- 라이트·다크 모드 모두 확인. 390px에서 렌더링된 본문 텍스트의 계산 색상을 점검한 결과, 작은 글자 4.5:1 및 큰 글자 3:1 기준 미달 항목 없음. 이 검사는 이미지 내부 글자와 그라디언트 픽셀까지 검증하는 전체 접근성 인증은 아니다.
- 다크 모드에서 소식, 플랫폼, 경영 판단, 제품 화면, 도입 흐름, AI·뷰어, 솔루션, SpinFire, 고객사, PLM 필요 상황, FAQ, 상담 섹션의 배경색이 모두 `rgb(16, 23, 25)`인 것을 확인.
- 제품 전환 후 Clip PDM 상세 내용과 대비 확인. 브라우저 경고·오류 로그 없음.
- 마지막 모바일 상담 위치 수정 후 14개 테스트·구문 검사·빌드를 다시 통과했다. 320px에서 로고·상담·메뉴 사이 겹침 없음. 1263px에서는 기존 데스크톱 메뉴가 유지되고 모바일 상담 링크는 숨겨짐을 확인했다.
