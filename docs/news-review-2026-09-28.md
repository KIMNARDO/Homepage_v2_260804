# 팹스넷 소식 통합 검토안

## 검토 범위와 승인 상태

운영 코드 기준 작업 폴더 `papsnet-production`에서 만든 로컬 검토안이다. Git 커밋·푸시와 운영 배포는 하지 않았다. 기존 히어로, 플랫폼, 제품 소개, SpinFire 제품 섹션과 자료는 유지했다.

미리보기: `http://127.0.0.1:5174/#news`

## 화면 구성

- 방송과 강의 사진의 별도 섹션을 **팹스넷 소식** 하나로 통합했다.
- 전체·언론 보도·교육 활동·기업 소식 분류를 제공한다. 첫 소식은 큰 이미지로, 나머지는 작은 목록으로 표시한다.
- 클릭하면 같은 페이지에서 상세 창이 열린다. 강의 사진 20장을 순서대로 또는 썸네일로 선택할 수 있다. Escape로 닫으면 원래 항목에 키보드 포커스가 돌아온다.
- 방송 소식의 ‘방송 보기’를 누르면 상세 창과 YouTube 플레이어를 함께 열고 재생을 요청한다. 상세 주소에 직접 접속하면 기본 재생 컨트롤을 보여준다. 상세 창을 닫으면 플레이어도 제거한다.
- 기사에는 짧은 소개와 원문 링크를 제공한다. 계약 소식에서는 기존 SpinFire 제품 섹션으로 이동한다.
- 강의 문의 링크를 제거했다. 교육 활동 사진과 소개는 유지했다.
- 소식은 `content/news.json`에 등록한다. 분류별 건수와 페이지가 자동으로 갱신되며 한 페이지에 최대 네 건을 표시한다.

## 로고 수정

기존 로고 이미지는 이미 투명 PNG였지만, `.nav-logo-img-wrap`에 흰색 배경이 적용되어 있었다. 배경을 투명하게 바꾸고 내부 패딩을 제거했다. 이미지 색상은 그대로 사용한다. 오래된 수동 캐시 쿼리를 제거해 최신 CSS가 로드되도록 했다. 밝은 테마와 어두운 테마에서 모두 투명 배경을 확인했다.

## 검증

- 소식 데이터, 분류, 네 건 단위 페이지 처리, 비표시 항목, 빈 목록, 잘못된 데이터, HTML 문자 처리를 Node 테스트로 확인했다.
- 프로덕션 빌드를 완료하고 빌드 HTML에 네 소식이 포함되는지 확인했다.
- 1280px 데스크톱, 390px 및 320px 모바일 너비에서 가로 넘침과 사진 상세 창을 확인했다.
- 교육 사진 선택·방향키·Escape·닫기 후 포커스 복귀, 기사 원문 주소, 방송 플레이어 생성/제거, SpinFire 이동, 상세 주소 직접 연결을 확인했다. 외부 YouTube 영상의 전체 재생 완료 여부까지 검증한 것은 아니다.
- 기존 11개 주요 섹션의 HTML이 통합 작업 전과 동일한지 비교했다. 사진 네 장은 사용자 원본·공개 폴더·빌드 결과의 SHA-256이 모두 같았다.
- SpinFire 한국어 소개서(221,048바이트)가 빌드에 유지됨을 확인했다.

검토 캡처는 `output/news-review/`에 저장했다. 소식 추가 절차는 `news-content-guide.md`에 정리했다.

## 강의 사진 추가 후속 검토

사용자가 추가 제공한 `KakaoTalk_20260928_180305561.jpg` 및 `_01`~`_15`의 16장을 기존 네 장 다음에 등록했다. 강의 소식은 한 건으로 유지하며 사진은 총 20장이다. 마지막 사진은 학교 전경이다.

- 원본 16장 합계: 42,389,841바이트. 원본 파일은 수정하지 않았으며 SHA-256으로 확인했다.
- 추가한 웹용 사진 16장 합계: 4,965,654바이트. 가로 1600px로 비율을 유지해 JPEG로 저장했다.
- 전체 20장의 별도 썸네일 합계: 217,382바이트. 가로 240px로 만들어 상세 사진 전체를 한꺼번에 불러오는 것을 피했다.
- 원본의 장면·색상·구도를 바꾸지 않았고, 기존 네 장의 파일과 대표 사진도 유지했다.
- 썸네일은 가로로 넘기며 선택하고, 선택한 사진이 보이도록 목록 위치를 자동으로 맞춘다. 사진 번호·전체 장수·설명을 표시한다. 키보드 방향키와 Home·End를 지원하며, 썸네일의 Tab 정지점은 선택된 한 곳으로 유지한다.
- 사진 20장과 썸네일 20장이 유효한 JPEG이고 빌드 결과에 동일하게 포함되는지 검사했다. 기존 소식 테스트 8개와 빌드를 통과했다.

사진 변환 기록: `output/news-review/hwagok-photo-manifest.json`.
데스크톱 검토 캡처: `output/news-review/hwagok-20-photos-desktop.png`.
운영 게시 및 Git 커밋·푸시는 여전히 사용자 승인 전이다.

## 방송 열기 및 1080p 후속 검토

기존에는 방송 소식을 누른 뒤 상세 창의 별도 ‘방송 재생’ 버튼을 한 번 더 눌러야 플레이어가 생성됐다. 방송 자체는 실제 영상과 재생 시간 진행을 확인했다. 별도 재생 단계를 제거하고 소식 카드 문구를 ‘방송 보기’로 바꿨다. 팹스넷 소개 구간(00:29–06:41), 화질 선택 안내, YouTube 원본 링크를 영상 바로 아래에 배치했다.

- 카드 클릭은 `autoplay=1`, 상세 주소 직접 접속은 `autoplay=0`으로 구분한다. 브라우저가 자동 재생을 제한해도 YouTube 기본 재생 컨트롤을 이용할 수 있다.
- 영상 창은 최소 높이 200px를 확보해 작은 화면에서도 플레이어 조작 공간을 유지한다.
- 실제 YouTube 화질 메뉴에서 1080p·720p·360p·144p를 확인하고 1080p를 선택했다.
- 이 선택은 현재 플레이어의 설정이다. 홈페이지에서 모든 방문자에게 1080p를 강제하는 설정으로 구현한 것은 아니다. YouTube는 `setPlaybackQuality`와 `suggestedQuality`를 지원하지 않으며 호출해도 무시한다고 명시한다. 작동하지 않는 화질 강제 매개변수는 추가하지 않았다.
- 공식 근거: https://developers.google.com/youtube/iframe_api_reference?hl=ko#october-24,-2019
- 모든 방문자에게 1080p 소스를 지정하려면 사용 가능한 1080p 원본 영상 파일을 확보한 뒤 자체 영상 플레이어로 제공하는 별도 방식이 필요하다.

후속 검증 결과:

- 목록에서 한 번 클릭해 실제 방송 화면과 자막 진행을 확인했다. 직접 주소에서는 `autoplay=0`과 YouTube 기본 재생 버튼을 확인하고 직접 재생했다.
- 닫기 후 iframe이 0개가 되고 스크롤 잠금이 풀리며, 방송 보기 링크로 포커스가 돌아오는 것을 확인했다.
- 390px 및 320px 너비에서 페이지·상세 창 가로 넘침이 없고 영상 높이가 200px 이상이다. 강의 갤러리 20장과 다음 사진 전환도 정상이다.
- 소식 데이터 테스트 8개 통과. 최종 Vite 빌드 통과. 최종 브라우저 오류·경고 로그는 없었다.
- 빌드와 방송 재생을 동시에 수행하는 중 Node 메모리 부족과 브라우저 영상 프레임 종료가 한 차례 발생했다. 빌드를 `node --max-old-space-size=512 node_modules/vite/bin/vite.js build`로 다시 실행해 성공했고, 방송 창을 다시 열어 정상 재생 및 화질 1080p 표시를 확인했다. 두 현상의 인과관계는 확정하지 않았다.
- 확인 화면: `output/news-review/tv-direct-play-desktop.png`, `tv-direct-play-mobile.png`, `tv-1080p-confirmed.png`.

Git 스테이징·커밋·푸시 및 운영 배포는 하지 않았다.
